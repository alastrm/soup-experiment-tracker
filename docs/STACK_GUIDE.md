# Stack and implementation boundaries (project choice, not Soup requirements)

**Backend:** Python 3.12, FastAPI, Pydantic v2, SQLAlchemy 2.x with asyncio + asyncpg, Alembic migrations, PostgreSQL. Use pytest + httpx for API/integration verification. Pin compatible versions at implementation time and record them; avoid guessing a latest release.

**Frontend:** Next.js App Router, React, TypeScript, minimal CSS (Tailwind only if already useful). The UI is a client-side consumer of the FastAPI backend. Next.js is **not** a second API server or persistence layer. Playwright E2E must exercise actual rendered Next pages, not mocked fetch responses.

**Live updates:** FastAPI `StreamingResponse` SSE (`text/event-stream`); DB-backed replay with bounded queries. Never hold one DB transaction/session through a long stream. The browser uses `fetch()` with the bearer header and an SSE parser because native `EventSource` cannot set `Authorization`. Respect standard SSE framing (`id:`, `event:`, `data:`, blank-line delimiter), heartbeats, reconnect `Last-Event-ID`, and cancellation. Client updates cursor only after an event is successfully applied.

**API authorization:** browser requests directly to a browser-reachable FastAPI origin (`http://localhost:8000` in the local Compose demo); Next.js served at `http://localhost:3000`. Configure explicit CORS origin, auth header allowance and no private caching. `NEXT_PUBLIC_API_BASE_URL` may contain only a public **URL**, never a token. Never tell browser code to call Docker-only `http://api:8000`. A no-account demo bootstrap that creates a project/key is a documented design choice, not secure multi-user identity management.

**Database invariants:** per-run row lock in one PostgreSQL transaction; per-run cursor stored on `runs` and incremented only for newly inserted committed metrics. Use a canonical batch digest with defined order/encoding; unique constraints for `(run_id, batch_id)` and `(run_id, event_id)`. Event `step` is logical order; `seq` is persisted/replay order. Write and dedup metadata commit atomically. Demonstrate PostgreSQL, not SQLite, in integration tests.

**Phase 1 contract refinements:** [API_CONTRACT.md](API_CONTRACT.md) is authoritative for endpoint shapes, canonical bytes, bounds and errors. Use thin routes, explicit service transactions and scoped persistence queries. Each concurrent task owns its AsyncSession. Mutations use READ COMMITTED with auth inside the transaction, project FOR SHARE/revalidate then fresh scoped run FOR UPDATE; rotation project FOR UPDATE/revalidate. Commit before response, never in deferred dependency cleanup. Unknown commit acknowledgement requires identical batch retry. Snapshot uses short read-only REPEATABLE READ set before first SQL, <=128 greatest-(step,seq) winners plus count/H, not full history. SSE polls use separate short consistent views of `(cursor,H]`, release sessions before network sends. No migration substitute via create_all.

**Stream/browser refinements:** enforce the contract's send deadline at ASGI transport, independent fixed-tick key watchdog including pool timeout, bounded pages/frames and 100-stream/process admission. A generator-only timeout/page-level key check cannot protect blocked sends. Handle cancellation/cleanup explicitly. Client snapshot/reducer and applied cursor form one state transition; control frames do not advance cursor. Abort all old-generation callbacks/timers on key/run change. Configure exact CORS headers including Last-Event-ID and no-store on errors/key responses; keep keys only in ephemeral browser memory, with no server actions/API handlers or secret-bearing SSR HTML. These are implementation obligations, not verified guarantees.

**Docker:** target three main services (`web`, `api`, `db`); `docker compose up` must be sufficient to start the application once implemented. Use health/readiness gating, migrations with explicit startup behavior, example environment configuration and persistent DB volume. Avoid Redis, broker, task workers and production orchestration unless a test justifies them.

**Testing division:** pytest covers schema bounds, project-aware API auth, transaction/duplicate/rollback/key rotation. Playwright covers the Next.js rendered page, forced network/SSE interruption, recovery and comparison with a separate authoritative DB query. Keep raw output. Never claim the throughput verdict before measurement.

**Expected directory direction (not mandated until Phase 2):** `backend/app/` and `backend/alembic/`, `frontend/src/app/`, `tests/` or `backend/tests/` + `frontend/e2e/`, `docs/`, `artifacts/test-output/`. Do not scaffold these directories during design-only Phase 1.
